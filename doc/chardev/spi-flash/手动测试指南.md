# chardev_spi_flash 手动测试指南（纯命令版）

> 全篇只给手动命令，不需要跑脚本。带 ✅实测 的输出都是在这套环境里跑出来的原样结果。
> 结构与设计说明见[设计文档](设计文档.md)；一键验收是
> [`tests/chardev/spi-flash/verify_qemu.sh`](../../../tests/chardev/spi-flash/verify_qemu.sh)（22 项断言）。

**四条前提**：

1. **对外是标准 spidev ABI**（`/dev/spidevB.C` + `SPI_IOC_*`）：任何按 spidev 写的用户态程序都能用，
   libobject 的 `Spi` HAL / [`test_spi.c`](../../../../libobject/tests/board/test_spi.c:1) 一行不改。
2. **与内核自带 spidev 互斥**（SPI 总线 1:1 绑定）：内核 spidev 是内建的，开机就绑定了 CS0 上的
   `spidev@0` 节点，所以**必须先 unbind**，`insmod` 本模块才会 probe。
3. **`/dev/spidev0.0` 由 class+device 自动生成**（devtmpfs）；没有 devtmpfs 时要自己 `mknod`（见 §3.1）。
4. **读 JEDEC ID 要重试**：QEMU virt + PL022 上连续发消息会"奇偶交替"（奇数条读到 `20 ba 17`，
   偶数条读回全 0）——**内核自带 spidev 表现完全相同**，是平台现象，见[设计文档 §6](设计文档.md)。

## 1. 编译（手动命令）

**驱动**：

```sh
cd /home/alan/workspace/linux-kmods
make -C /home/alan/workspace/linux-4.9.263 M=$PWD/drivers/chardev/spi-flash \
     ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- modules
# 产物：drivers/chardev/spi-flash/chardev_spi_flash.ko
```

**用户态测试程序**（必须 `-static`：busybox rootfs 没有动态库）：

```sh
cd tests/chardev/spi-flash
mkdir -p build
aarch64-linux-gnu-gcc -static -O2 -Wall -o build/spidev_test spidev_test.c
# ✅实测：build/spidev_test 是 "ELF 64-bit ... ARM aarch64, statically linked"
```

## 2. 启动 QEMU（手动命令行）

```sh
/home/alan/workspace/qemu/build/qemu-system-aarch64 \
  -M virt -cpu cortex-a57 -m 2G \
  -kernel /home/alan/workspace/linux-4.9.263/arch/arm64/boot/Image \
  -initrd /home/alan/workspace/busybox-1.33.1/initramfs.cpio.gz \
  -nographic \
  -virtfs local,path=/home/alan/workspace/linux-kmods,mount_tag=kmods,security_model=none,id=kmods \
  -append "console=ttyAMA0 rdinit=/linuxrc"
```

等到 `Please press Enter to activate this console.` 后**按回车**进 shell（`Ctrl-A c` 切 monitor）。

## 3. 客户机里手动验证

### 3.0 先看清起点：spidev 占着器件

```sh
mkdir -p /mnt
mount -t 9p -o trans=virtio,version=9p2000.L kmods /mnt

cat /sys/bus/spi/devices/spi0.0/modalias        # ✅实测 spi:dh2228fv
readlink -f /sys/bus/spi/devices/spi0.0/driver  # ✅实测 /sys/bus/spi/drivers/spidev
ls -l /dev/spidev0.0                            # ✅实测 crw-rw---- ... 153, 0 /dev/spidev0.0
cat /sys/class/spidev/spidev0.0/dev             # ✅实测 153:0
dmesg | grep -i pl022                           # ✅实测 ssp-pl022 90d0000.spi: ARM PL022 driver, device ID: 0x00041022
```

### 3.1 互斥：不 unbind 就 insmod，是不会 probe 的

```sh
insmod /mnt/drivers/chardev/spi-flash/chardev_spi_flash.ko; echo RC=$?
ls /sys/class/chardev_spi_flash/ 2>&1
```

✅实测：

```
RC=0
ls: /sys/class/chardev_spi_flash/: No such file or directory
```

即：模块**注册成功但没有探到器件**（1:1 绑定，器件已被 spidev 占着）。
`dmesg` 里只有 `chardev_spi_flash: loading out-of-tree module taints kernel.`，**没有** `ready:` 日志。

```sh
rmmod chardev_spi_flash
```

### 3.2 切换：unbind 内核 spidev → insmod 本驱动

```sh
echo spi0.0 > /sys/bus/spi/drivers/spidev/unbind; echo RC=$?
ls -l /dev/spidev0.0 2>&1                       # ✅实测：No such file or directory（节点被摘掉）

insmod /mnt/drivers/chardev/spi-flash/chardev_spi_flash.ko
dmesg | tail -1
ls -l /dev/spidev0.0
ls /sys/class/chardev_spi_flash/
readlink -f /sys/bus/spi/devices/spi0.0/driver
cat /sys/class/chardev_spi_flash/spidev0.0/dev
```

✅实测：

```
chardev_spi_flash spidev0.0: ready: /dev/spidev0.0 (bus 0 cs 0, 12000000 Hz)
crw-rw----    1 0        0         240,   0 ... /dev/spidev0.0
spidev0.0
/sys/bus/spi/drivers/chardev_spi_flash
240:0
```

> **dev 号从 `153:0`（内核 spidev）变成 `240:0`（本驱动）** —— 一眼看出节点换主人了。
> 如果 `/dev/spidev0.0` 没出现（系统没有 devtmpfs）：
> ```sh
> mknod /dev/spidev0.0 c $(awk -F: '{print $1}' /sys/class/chardev_spi_flash/spidev0.0/dev) 0
> ```

```sh
cp /mnt/tests/chardev/spi-flash/build/spidev_test /tmp/
/tmp/spidev_test /dev/spidev0.0
```

**上面那句"重试样本"是在说平台现象**：同一块板子上连续读，会

```

第 3 次：20 ba 17
...
```

（`spidev_test` 因此最多试 4 次；把 `/dev/spidev0.0` 换回内核 spidev 跑同一个程序，交替规律完全一样
——见[设计文档 §6](设计文档.md)的对照实验表。）

### 3.4 `read()` / `write()`：裸半双工

```sh
# 写 4 字节（0x9F + 3 个 0x00）
printf '\237\000\000\000' > /dev/spidev0.0; echo RC=$?
# ✅实测：RC=0

# 读 4 字节
head -c 4 /dev/spidev0.0 | od -An -tx1
# ✅实测： 9f 00 00 00   （这是"一次只有读"的操作里回移出的字节，
#                        含义由器件协议决定，不是"传感器读数"；
#                        要看 JEDEC ID 必须用 SPI_IOC_MESSAGE(2)）
```

> 注意 `read()`/`write()` 各自是**一次独立操作**（CS 会在两次之间释放），
> 所以想"先发命令再读数据"必须用 `SPI_IOC_MESSAGE(2)`（就是 `spidev_test` 与 `test_spi.c`
> 的 `write_then_read` 做的事）。

### 3.5 错误路径（手工复现 errno）

```sh
# 打开着文件时卸不掉（fops.owner 加引用）
exec 9</dev/spidev0.0
rmmod chardev_spi_flash
exec 9<&-
```

✅实测：

```
rmmod: remove 'chardev_spi_flash': Resource temporarily unavailable
```

> ⚠️ busybox 的 `rmmod` 在**失败时退出码仍是 0**，所以别用 `$?` 判断成功与否，
> 用 `grep chardev_spi_flash /proc/modules` 看模块还在不在。

### 3.6 反复加载/卸载（30 次）

```sh
n=0; while [ $n -lt 30 ]; do
    rmmod chardev_spi_flash; insmod /mnt/drivers/chardev/spi-flash/chardev_spi_flash.ko
    n=$((n+1))
done
rmmod chardev_spi_flash
ls /dev/spidev0.0            # ✅实测：No such file or directory
```

> 每次 `insmod` 都会重新 probe（因为器件此刻没有驱动），节点也随之重建；没有残留。

### 3.7 换回内核 spidev

```sh
echo spi0.0 > /sys/bus/spi/drivers/spidev/bind; echo RC=$?
ls -l /dev/spidev0.0
cat /sys/class/spidev/spidev0.0/dev
```

✅实测：

```
RC=0
crw-rw----    1 0        0         153,   0 ... /dev/spidev0.0
153:0
```

## 4. 现象速查表

| 现象 | 原因 / 处理 |
|---|---|
| `insmod` 成功但**没有** `/dev/spidev0.0`、没有 `ready:` 日志 | 器件被内核 spidev 占着（1:1 绑定）→ 先 `echo spi0.0 > /sys/bus/spi/drivers/spidev/unbind`（§3.1） |
| `unbind` 后 `/dev/spidev0.0` 没了 | 正常：spidev 的 class device 被摘掉；`insmod` 本驱动后会重建（dev 号变 240:0） |
| 读 ID 得到 `00 00 00` | QEMU/PL022 的"奇偶交替"平台现象（内核 spidev 一样）→ 重试，或见设计文档 §6 |
| `/tmp/spidev_test: Text file busy` / `Permission denied` | 9p 挂载不一定可执行 → 先 `cp` 到 `/tmp` 再跑 |
| `cat /dev/spidev0.0` 一直返回 0 字节 | 这是**传输端点**不是传感器接口：`read/write` 是裸收发，长度由你给的 `count` 决定 |
| `rmmod` 打印 `Resource temporarily unavailable` | 有进程还开着 `/dev/spidev0.0`（`fops.owner` 引用）→ 关掉再卸 |
| `rmmod` 打印 `Module chardev_spi_flash is not currently loaded` | 之前已经卸掉了（或从未 `insmod`） |
| 开机 `dmesg` 里有 `ssp-pl022 90d0000.spi: Failed to work in dma mode` | PL022 无 DMA 时正常提示，与本驱动无关 |
