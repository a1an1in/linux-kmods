# chardev_i2c_tmp105 手动测试指南（纯命令版）

> 全篇只给手动命令，不需要跑脚本。带 ✅实测 的输出都是在这套环境里跑出来的原样结果。
> 结构与设计说明见[设计文档](设计文档.md)；一键验收是
> [`tests/chardev/i2c-tmp105/verify_qemu.sh`](../../../tests/chardev/i2c-tmp105/verify_qemu.sh)（18 项断言）。

**四条前提**：

1. **启动不要加 `-dtb`**：自研 QEMU 会自生成含 `/i2c@9060000/tmp105@48` 的 FDT（hwmon 驱动要用）。
2. **本驱动不占 0x48**：它只 `i2c_get_adapter()` 拿适配器引用 + `i2c_transfer` 发消息，
   所以**可以和 `hwmon_i2c_tmp105` 同时加载**（正好对照两种接口）。
3. **/dev/tmp105 由 class+device 自动生成**（devtmpfs）；若系统没有 devtmpfs，要自己
   `mknod /dev/tmp105 c $(awk '$2=="tmp105"{print $1}' /proc/devices) 0`。
4. **测量温度只能宿主侧改**（QEMU 的 `temperature` 属性），客户机里改不了；能改的只有阈值。

## 1. 编译（手动命令）

**驱动**：

```sh
cd /home/alan/workspace/linux-kmods
make -C /home/alan/workspace/linux-4.9.263 M=$PWD/drivers/chardev/i2c-tmp105 \
     ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- modules
# 产物：drivers/chardev/i2c-tmp105/chardev_i2c_tmp105.ko
```

**用户态测试程序**（必须 `-static`：busybox rootfs 没有动态库）：

```sh
cd tests/chardev/i2c-tmp105
mkdir -p build
aarch64-linux-gnu-gcc -static -O2 -Wall \
    -I ../../../drivers/chardev/i2c-tmp105 \
    -o build/ioctl_test ioctl_test.c
# ✅实测：build/ioctl_test 是 "ELF 64-bit ... ARM aarch64, statically linked"
```

## 2. 启动 QEMU（手动命令行）

```sh
/home/alan/workspace/qemu/build/qemu-system-aarch64 \
  -M virt -cpu cortex-a57 -m 2G \
  -kernel /home/alan/workspace/linux-4.9.263/arch/arm64/boot/Image \
  -initrd /home/alan/workspace/busybox-1.33.1/initramfs.cpio.gz \
  -nographic \
  -monitor unix:/tmp/tmp105-mon.sock,server,nowait \
  -virtfs local,path=/home/alan/workspace/linux-kmods,mount_tag=kmods,security_model=none,id=kmods \
  -append "console=ttyAMA0 rdinit=/linuxrc"
```

等到 `Please press Enter to activate this console.` 后**按回车**进 shell；
串口与 monitor 复用终端（`Ctrl-A c` 切换，或另开终端用 `nc -U /tmp/tmp105-mon.sock`）。

## 3. 客户机里手动验证

### 3.1 加载驱动：节点是自动出现的

```sh
mkdir -p /mnt
mount -t 9p -o trans=virtio,version=9p2000.L kmods /mnt

insmod /mnt/drivers/chardev/i2c-tmp105/chardev_i2c_tmp105.ko
dmesg | tail -2
ls -l /dev/tmp105
ls -l /sys/class/tmp105/
```
✅实测：
- `chardev_i2c_tmp105: ready: /dev/tmp105 (i2c-0 addr 0x48) T=25000mC`
- `crw-rw---- 1 0 0 240, 0 ... /dev/tmp105`（**240 是内核动态分配的 major**）
- `/sys/class/tmp105/tmp105 -> ../../devices/virtual/tmp105/tmp105`

> 如果 `/dev/tmp105` 没出现（系统没有 devtmpfs）：
> ```sh
> awk '$2 == "tmp105" { print $1 }' /proc/devices     # 取 major
> mknod /dev/tmp105 c <那个数字> 0
> ```

### 3.2 `read()`：读当前温度（十进制文本，单位 m°C）

```sh
cat /dev/tmp105
```
✅实测：`25000`

### 3.3 `write()`：写上限阈值 T_HIGH

```sh
echo 50000 > /dev/tmp105; echo RC=$?      # ✅实测 RC=0（阈值 50.0 °C）
echo abc > /dev/tmp105;   echo RC=$?      # ✅实测：sh: write error: Invalid argument / RC=1
```

### 3.4 `ioctl()`：用配套的用户态程序（阈值/报警/错误码）

9p 挂载不保证"可直接执行"，先拷到 `/tmp`（tmpfs）再跑：

```sh
cp /mnt/tests/chardev/i2c-tmp105/build/ioctl_test /tmp/
/tmp/ioctl_test /dev/tmp105
```
✅实测（11 项全过）：

```
  [PASS] read() 返回 6 字节：「25000
」
  [PASS] TMP105_IOC_GET_TEMP = 25000 mC
  [PASS] TMP105_IOC_SET_TMAX(20000) 成功
  [PASS] GET_TMAX 读回 20000（与写入一致）
  [PASS] GET_ALARM = 1（阈值低于当前温度）
  [PASS] GET_ALARM = 0（阈值高于当前温度）
  [PASS] write("30000") 返回 5（= 消费的字节数）
  [PASS] 未知命令返回 ENOTTY
  [PASS] magic 不对返回 ENOTTY
  [PASS] NULL 指针返回 EFAULT
  [PASS] write("abc") 返回 EINVAL
== ioctl_test: PASS=11 FAIL=0 ==
```

### 3.5 与 hwmon 驱动共存（同一颗芯片，两个接口）

```sh
insmod /mnt/drivers/hwmon/i2c-tmp105/hwmon_i2c_tmp105.ko
HW=$(cat /sys/class/hwmon/hwmon0/temp1_input)
CH=$(cat /dev/tmp105)
echo "hwmon=$HW /dev=$CH"
```
✅实测：`hwmon=25000 /dev=25000`（两个驱动同时绑定同一颗芯片，互不影响）

### 3.6 卸载与残留

```sh
rmmod chardev_i2c_tmp105
ls /dev/tmp105                # ✅实测：No such file or directory
ls /sys/class/tmp105/         # 目录也没了
cat /sys/class/hwmon/hwmon0/temp1_input   # ✅hwmon 驱动不受影响，仍可读
```

## 4. 改"环境温度"（宿主侧，制造动态条件）

方式 A（`Ctrl-A c` 进 monitor）：

```
(qemu) qom-set /machine/unattached/device[10] temperature -6000
```

方式 B（另一个宿主终端，`nc -U`）：

```sh
printf 'qom-get /machine/unattached/device[10] temperature\n' | nc -U /tmp/tmp105-mon.sock
printf 'qom-set /machine/unattached/device[10] temperature -6000\n' | nc -U /tmp/tmp105-mon.sock
```

回串口验证（负值也能正确读出——这正是踩过的"返回值二义性"坑）：

```sh
cat /dev/tmp105        # ✅实测：-6000
```

## 5. 现象速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `/dev/tmp105` 不存在 | insmod 没成功，或系统没有 devtmpfs | 看 `dmesg`；必要时按 `/proc/devices` 的 major 手动 `mknod` |
| `cat /dev/tmp105` 报 `Invalid argument` | 早期版本的坑：负温度被当错误码返回 | 本驱动已修（`int *out` 出参）；确认用的是当前代码 |
| `cat /dev/tmp105` 报 `Remote I/O error` | 器件不在（`addr` 参数写错 / 器件没挂） | 默认 0x48；`insmod chardev_i2c_tmp105.ko addr=0x49` 可复现错误路径 |
| `echo 50000 > /dev/tmp105` 报 `Invalid argument` | 内容不是整数，或超过 1 个缓冲（`count >= 32`） | 写十进制整数，如 `50000` |
| `ioctl_test` 跑不起来（`Permission denied`） | 9p 挂载不允许直接执行 | `cp` 到 `/tmp` 再执行 |
| `rmmod` 报 `Module ... is in use` | 还有进程开着 `/dev/tmp105` | 关掉 `cat`/测试程序（`fops.owner` 机制，属正常保护） |
| 忘记 `rmmod` 就 `insmod` 另一个 | 名字不同没关系，两者可共存 | 但同一模块不能重复加载：`insmod` 会报 `File exists` |
