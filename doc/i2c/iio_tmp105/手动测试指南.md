# iio_tmp105 手动测试指南（只用驱动接口）

> **验证入口只有一个：我们驱动导出的 IIO 接口**
> `/sys/bus/iio/devices/iio:deviceN/{name,in_temp_raw,in_temp_scale}`。
> 与 hwmon 版指南的区别：IIO 给的是 **raw + scale**，m°C 要自己换算
> （`raw * 1000 / 256`，scale=3.906250 正好等于 1000/256）。
> 全篇只给手动命令；带 ✅实测 的输出是在这套环境里跑出来的原样结果。
> 唯一"不经过驱动"的操作是宿主侧 `qom-set` 改环境温度（制造测试条件）。

**三条前提**：

1. **启动不要加 `-dtb`**（同 hwmon 版）：让 QEMU 自生成含
   `tmp105@48`（`compatible = "ti,tmp105"`）的 FDT，否则不 probe。
2. **与 hwmon_tmp105 互斥**：两者都绑定 0x48，先 `rmmod hwmon_tmp105`
   再 `insmod iio_tmp105`（`chardev_tmp105` 不冲突，可共存）。
3. **读数是 raw 不是 m°C**：`in_temp_raw=6400` 表示 25.0 °C
   （6400 = 0x1900）；负温度 raw 是负数（−6.5 °C → `-1664`）。

## 3. 驱动接口验证（客户机 shell）

### 3.1 加载与定位

```sh
mkdir -p /mnt
mount -t 9p -o trans=virtio,version=9p2000.L kmods /mnt
insmod /mnt/drivers/i2c/iio_tmp105/iio_tmp105.ko
dmesg | tail -3
for d in /sys/bus/iio/devices/iio:device*; do
    [ "$(cat $d/name)" = tmp105 ] && echo "found: $d"
done
```

✅实测：`iio_tmp105 0-0048: tmp105 iio at 0x48 on Synopsys DesignWare I2C adapter`
（设备树 `ti,tmp105` 匹配成功；按 `name` 定位，别写死 `iio:device0`。）

### 3.2 读 raw / scale，手算 m°C

```sh
DEV=<上一步 found 的路径>
cat $DEV/name          # tmp105
cat $DEV/in_temp_raw   # 6400        <- 8.8 定点原始值（25.0 °C）
cat $DEV/in_temp_scale # 3.906250    <- m°C/LSB
echo $(( $(cat $DEV/in_temp_raw) * 1000 / 256 ))   # 25000 (m°C)
```

换算就是 hwmon 的 `temp1_input` 同款公式——**IIO 把换算挪给了用户态**。

### 3.3 边界与负温度（宿主侧 qom-set 造条件）

```sh
python3 scripts/qmp_dev.py /tmp/iio105.sock set --match tmp105 --value -6250
cat $DEV/in_temp_raw    # -1664（-6.5 °C：9 位模式量化，-6250 落到 0.5 °C 网格）
echo $(( $(cat $DEV/in_temp_raw) * 1000 / 256 ))   # -6500

python3 scripts/qmp_dev.py /tmp/iio105.sock set --match tmp105 --value -6000
cat $DEV/in_temp_raw    # -1536 -> -6000（可精确表示，符号扩展正确）

python3 scripts/qmp_dev.py /tmp/iio105.sock set --match tmp105 --value 30000
cat $DEV/in_temp_raw    # 7680 -> 30000（动态跟随，不是读死值）
```

### 3.4 反向用例

```sh
echo 1 > $DEV/in_temp_raw          # 所有文件 0444（v1 无 write_raw），写入被拒
echo 20000 > $DEV/in_temp_scale    # 同上
```

✅实测：`echo: write error: Invalid argument`（`-EINVAL`）。
**教学点**：为什么不是 Permission denied？——root 有 `CAP_DAC_OVERRIDE`，
0444 文件的**打开**能过 VFS 权限检查；真正失败在 write 阶段：kernfs 发现
该属性没有 store 回调，返回 `-EINVAL`（见内核 `fs/kernfs/file.c` 的
`kernfs_fop_write()`，`if (ops->write) ... else len = -EINVAL;`）。

### 3.5 器件不在地址上（可选，仿 hwmon §3.6）

```sh
echo iio_tmp105 0x49 > /sys/bus/i2c/devices/i2c-0/new_device
cat /sys/bus/iio/devices/iio:device*/in_temp_raw   # Remote I/O error（-EREMOTEIO）
echo 0x49 > /sys/bus/i2c/devices/i2c-0/delete_device
```

### 3.6 反复加载/卸载

```sh
rmmod iio_tmp105 && ls /sys/bus/iio/devices
i=0; while [ $i -lt 100 ]; do
    rmmod iio_tmp105; insmod /mnt/drivers/i2c/iio_tmp105/iio_tmp105.ko
    i=$((i+1))
done
ls /sys/bus/iio/devices     # 与加载前一致（无残留）
dmesg | tail -5             # 无 Oops / BUG / WARNING
```

## 4. 现象速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `/sys/bus/iio/devices` 里没有 name=tmp105 | 设备树没匹配（加了 `-dtb`）；或 hwmon_tmp105 已占 0x48 | 不加 `-dtb`；先 `rmmod hwmon_tmp105` |
| `in_temp_raw` 报 Remote I/O error | 该地址上没有器件（如 0x49） | 检查 `reg`/`new_device` 地址 |
| 读数 `-1664` 而不是 -6250 对应的值 | 器件默认 9 位（0.5 °C 步进） | 正常，qom-set -6000 验证精确值 |
| `cat in_temp_scale` 不是 3.906250 | 换算实现有 bug | 检查 read_raw 的 VAL_INT_PLUS_MICRO 两段 |
| `insmod` 报 Device or resource busy（模块符号） | hwmon_tmp105 还在 | 先卸载它（一个地址一个 client 驱动） |
| 开机 `WARNING ... i2c_dw_clk_rate` | DesignWare I2C 自带 WARN（0.9s，早于本模块） | 忽略 |
