# iio_i2c_tmp105 设计文档（IIO 子系统）

> 目标：**用同一颗 TMP105 再实现一种外壳——IIO 子系统**，与
> [`hwmon_i2c_tmp105`](../../hwmon/i2c-tmp105/设计文档.md) 对照着学"同一器件、
> 不同子系统"长什么样。
> 代码：[`drivers/iio/i2c-tmp105/iio_i2c_tmp105.c`](../../../drivers/iio/i2c-tmp105/iio_i2c_tmp105.c) ·
> 手动命令：[手动测试指南](手动测试指南.md) ·
> 一键验收：[`tests/iio/i2c-tmp105/verify_qemu.sh`](../../../tests/iio/i2c-tmp105/verify_qemu.sh)

## 1. 目标与范围

| 做 | 不做（扩展点见 §7） |
|---|---|
| I2C client 驱动 + 设备树自动匹配（`ti,tmp105`），结构同 hwmon_i2c_tmp105 | 阈值/事件：IIO 事件是**推送**模型（`iio_push_event`），需要 ALERT 引脚接中断；QEMU virt 没把这根线接出来 |
| `in_temp_raw` + `in_temp_scale`（IIO 标准 raw×scale 模型） | `in_temp_input`（PROCESSED）：留给用户态自己算，正好教学 |
| devm 全托管：`devm_iio_device_alloc` + `devm_iio_device_register`，remove 留空 | 缓冲区/trigger（kfifo、CONFIG 变分辨率）、多通道 |

**与 hwmon_i2c_tmp105 互斥**：两个模块都匹配 `ti,tmp105@0x48`，i2c 核心一个
从机地址只允许一个 client 驱动绑定（开发规范 §8.1）——**同一时刻只能
加载一个**；`chardev_i2c_tmp105` 不占地址，可与任一共存。

## 2. IIO 模型速讲（对照 hwmon）

IIO 的核心思想：**驱动不换算，只报"原始值 + 换算系数"**，由用户态
（libiio、`lib/`工具或 shell）按 processed 公式算物理量：

```
processed = (raw + offset) * scale
本器件（摄氏原点，无 offset）：m°C = in_temp_raw * in_temp_scale
```

| 概念 | hwmon_i2c_tmp105 | iio_i2c_tmp105 |
|---|---|---|
| 设备对象 | `hwmon_device`（with_info） | `struct iio_dev`（`devm_iio_device_alloc`） |
| 私有数据 | `devm_kzalloc` 自管 | `iio_priv(indio_dev)`（iio_dev 后面的私有区） |
| "暴露什么" | `HWMON_T_*` 位掩码 → `temp1_input` | `info_mask_separate` 位掩码 → `in_temp_raw`/`in_temp_scale` |
| 读回调 | `.read(dev, type, attr, ch, val)` | `.read_raw(indio_dev, chan, &val, &val2, mask)` |
| 数值模型 | 驱动算好 m°C 一个数 | raw（整数）+ scale（`val.val2` 定点），用户态乘 |
| 文件名 | `/sys/class/hwmon/hwmonN/temp1_input` | `/sys/bus/iio/devices/iio:deviceN/in_temp_raw` |
| 单位约定 | sysfs 文件里直接是 m°C | 约定 processed 单位 m°C，scale 单位 m°C/LSB |

> 两个子系统的 info_mask 与 `HWMON_T_*` 是**同一思想**：驱动只声明
> "有哪些属性"，文件名由核心按 ABI 生成——这就是跨驱动统一命名的来源。

## 3. 器件与换算

寄存器表与数据格式与 [`hwmon_i2c_tmp105 设计文档 §3`](../../hwmon/i2c-tmp105/设计文档.md)
完全一致（同一颗芯片）：0x00 TEMPERATURE（8.8 定点、12 位有效、有符号）、
0x01 CONFIG、0x02 T_LOW、0x03 T_HIGH。

- raw：0x00 两字节按大端拼成 int16 **原样暴露**（25.0 °C → `6400`，
  −6.5 °C → `-1664`）
- scale：1 LSB = 1000/256 m°C = **3.90625**，IIO 用 `IIO_VAL_INT_PLUS_MICRO`
  两段表示（`*val=3; *val2=906250`），sysfs 显示 `3.906250`
- 换算：`m°C = raw * 1000 / 256`（shell 整数运算即可，与 hwmon 同公式）
- 器件上电默认 CONFIG=0 → 9 位有效（0.5 °C 步进）：`qom-set -6250` 的
  raw 落在 `-1664`（= −6.5 °C），详见 hwmon 文档 §12.1

## 4. 代码走读

```
probe:
  devm_iio_device_alloc(&client->dev, sizeof(*data))   ← iio_dev+私有区一次分配
  data = iio_priv(indio_dev)
  indio_dev->name = "tmp105"        ← 用户态 ABI（iio:deviceN/name），不随模块名变
  indio_dev->modes = INDIO_DIRECT_MODE
  indio_dev->channels = tmp105_channels   ← .type=IIO_TEMP + info_mask_separate
  indio_dev->info = &tmp105_info          ← .read_raw
  devm_iio_device_register(&client->dev, indio_dev)   ← remove 留空的全部理由
```

- **不设 `.indexed`**：单通道器件的文件名没有 `0` 后缀（`in_temp_raw`
  而不是 `in_temp0_raw`），与树内参考 `drivers/iio/temperature/tmp006.c`
  （4.9 版）一致
- **read_raw 两分支**：`IIO_CHAN_INFO_RAW` → `tmp105_read_word()` 读
  0x00，s16 有符号原样给 `*val`（**负值不是错误**——返回值只表达错误，
  同开发规范 §8.6 的坑）；`IIO_CHAN_INFO_SCALE` → 闭式计算
  `1000/256` 的整数+小数两段，不写死 3.90625
- **寄存器访问**与 hwmon_i2c_tmp105 相同（SMBus word swapped 优先，
  `i2c_transfer` 组合事务退化 + mutex 串行化）；按开发规范 §1.5
  暂不抽公共代码（跨模块共享符号要 `EXPORT_SYMBOL*`）
- probe 只读 CONFIG 打日志，不作为失败条件（同 hwmon 纪律）

## 5. 对外 ABI

路径：`/sys/bus/iio/devices/iio:deviceN/`（按 `name` 定位，别写死 N；
IIO 设备同样**没有 /dev 节点**）。

| 文件 | 内容 | 权限 | 实测（出厂 25.0 °C） |
|---|---|---|---|
| `name` | `"tmp105"` | 0444 | `tmp105` |
| `in_temp_raw` | 有符号 8.8 定点原始值 | 0444 | `6400` |
| `in_temp_scale` | m°C/LSB | 0444 | `3.906250` |
| （换算） | `m°C = raw * 1000 / 256` | — | `25000` |

错误码：I2C 从机不应答 → `-EREMOTEIO`（`cat` 报 Remote I/O error）；
未知通道/信息 → `-EINVAL`。所有文件 0444（v1 无 write_raw）——root
写它们报 `-EINVAL` 而非 EACCES：root 的 `CAP_DAC_OVERRIDE` 让 open 过了
权限检查，失败发生在 write 阶段（kernfs 无 store 回调，见
`fs/kernfs/file.c` 的 `kernfs_fop_write()`）。

## 6. 测试设计（L1~L4）

| 层 | 内容 | 工具 |
|---|---|---|
| L1 | 原始寄存器对照（insmod **前**，绑定后 i2c-dev EBUSY） | `i2cget -y 0 48 0x00 w` |
| L2 | probe 日志、按 name 定位、`name/raw/scale` 三文件 | insmod + sysfs |
| L3 | QMP `qom-set` 改温度 → raw 换算跟随（−6250→−6500 量化、−6000、30000） | `scripts/qmp_dev.py` |
| L4 | `read_iio.sh` 全过、100 次 insmod/rmmod 无残留、日志无 Oops/BUG/WARNING | `verify_qemu.sh` |

## 7. 扩展点

1. **阈值/事件**：通道加 `event_mask`，实现 `read/write_event_value/config`，
   中断到来时 `iio_push_event()` → 用户态出现
   `in_temp_thresh_rising_value`、`events/in_temp0_thresh_rising_en` 等文件；
   前提是 ALERT 引脚接到了 GPIO/中断（需改 QEMU 机器或 dtb）
2. **PROCESSED**：info_mask 加 `BIT(IIO_CHAN_INFO_PROCESSED)`，read_raw 里
   直接返回 m°C → 核心生成 `in_temp_input`（与 hwmon 读数直接对照）
3. **分辨率/SAMP_FREQ**：写 CONFIG 的 R1:R0（9~12 位），挂到
   `IIO_CHAN_INFO_SAMP_FREQ` 或 ext_info 自定义属性
4. **多通道**：channels 数组加项（如差分/多传感器器件）

## 8. 实测结论（`tests/iio/i2c-tmp105/verify_qemu.sh`，PASS=17 FAIL=0）

| 层 | 项 | 实测结果 |
|---|---|---|
| L1 | `i2cget -y 0 48 0x00 w` | `0x0019`（= 25.0 °C，与 QEMU 初始 `temperature=25000` 一致） |
| L2 | `dmesg` | `iio_i2c_tmp105 0-0048: tmp105 iio at 0x48 on Synopsys DesignWare I2C adapter` |
| L2 | `name` / 定位 | `tmp105`；按 name 定位到 `/sys/bus/iio/devices/iio:device0` |
| L2 | `in_temp_raw` / `in_temp_scale` | `6400` / `3.906250`；客户机换算 `6400*1000/256 = 25000`，与 L1 i2cget 对照一致 |
| L3 | `qom-set -6250` → raw 换算 | `-6500` m°C（9 位模式量化到 −6.5 °C，raw=−1664；`qom-get` 仍是 −6250） |
| L3 | `qom-set -6000` → raw 换算 | `-6000`（可精确表示，符号扩展正确） |
| L3 | `qom-set 30000` → raw 换算 | `30000`（动态跟随，不是读死值） |
| L4 | `read_iio.sh` | 全过（含"0444 只读保护"反向用例：root 写 `in_temp_raw` 报 `write error: Invalid argument`，即 kernfs 无 store 回调时的 `-EINVAL`，见 `fs/kernfs/file.c`） |
| L4 | 100 次 insmod/rmmod | 全部成功；`/sys/bus/iio/devices` 无残留；日志无 Oops/BUG/WARNING |

> 过程中踩掉的一个坑：初版 probe 忘打 `dev_info`，verify 的日志锚点
> `wait_for "iio at 0x48 on"` 匹配不到 —— 日志锚点是脚本与驱动的隐性
> 契约，改日志格式要同步改脚本（与 hwmon 版同款教训）。
