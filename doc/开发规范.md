# 开发规范（linux-kmods）

> 适用范围：本工程里所有内核模块（当前是
> [`hwmon_i2c_tmp105`](../drivers/hwmon/i2c-tmp105/hwmon_i2c_tmp105.c)、
> [`iio_i2c_tmp105`](../drivers/iio/i2c-tmp105/iio_i2c_tmp105.c)、
> [`chardev_i2c_tmp105`](../drivers/chardev/i2c-tmp105/chardev_i2c_tmp105.c)）。
> 目标：**每个模块都能通过 `./scripts/build.sh checkpatch`（0 errors / 0 warnings）、
> 能用 `tests/<子系统>/<总线>-<器件>/verify_qemu.sh` 一键验收**。

---

## 1. 目录与命名（新增驱动前先看这节）

### 1.1 两条正交规则

| 规则 | 取值 | 说明 |
|---|---|---|
| **目录按子系统分** | `drivers/hwmon/`、`drivers/iio/`、`drivers/chardev/`、`drivers/rtc/`… | 与内核树 `drivers/` 顶层同层次（内核本身就是子系统优先；`drivers/i2c/` 放的是总线控制器，不是器件驱动）。**总线作叶目录的名字前缀**，不作目录级 |
| **叶目录 = `<总线>-<器件>`** | `i2c-tmp105`、`spi-max31856`、`pcie-xdma`… | 同子系统的驱动聚合在一起；换总线（如 `drivers/hwmon/spi-max31856/`）自然并列 |

**一个驱动 = 一个目录**：

```
drivers/hwmon/i2c-tmp105/      ← 目录：<子系统>/<总线>-<器件>
    ├── Kbuild                 ← obj-m := hwmon_i2c_tmp105.o
    └── hwmon_i2c_tmp105.c         ← 主文件：与模块同名
```

- **主文件名 = 模块名 = `<子系统>_<总线>_<器件>`**（`hwmon_i2c_tmp105`、
  `iio_i2c_tmp105`、`chardev_i2c_tmp105`）：三个维度都写进名字，和叶目录
  `i2c-tmp105` 一一对应、只差子系统前缀；内核不允许同名模块同时加载
  （第二个 insmod 报 `-EEXIST`），而同一颗芯片完全可能在多个子系统各有
  一个驱动（TMP105 就同时有 hwmon/iio/chardev 三个），名字唯一才能共存、
  `rmmod` 才无歧义。
- 叶目录名（`i2c-tmp105`，连字符）**不等于**文件名（`hwmon_i2c_tmp105`，
  下划线）：目录名给人和 shell 看（不能带下划线混进模块名），文件名给
  Kbuild/git 看（不能带连字符，`obj-m := i2c-tmp105.o` 会让 Kbuild 把
  `-` 当参数分隔）。两者是同一组信息的两种合法拼写。

反例（不要这样）：

| 反例 | 问题 |
|---|---|
| `drivers/i2c-tmp105/`（顶层） | 顶层按子系统分；裸总线目录会把不同子系统的驱动混在一起，按子系统找不到全集 |
| `drivers/tmp105_hwmon/`、`drivers/hwmon/tmp105/` | 器件在前扫不出来；缺总线前缀——`drivers/iio/tmp105/` 若也叫 tmp105，模块名就撞了 |
| `drivers/hwmon/i2c-tmp105/` 里模块叫 `i2c-tmp105.ko` | 同芯片多子系统会得到多个同名模块：无法同时加载（-EEXIST，chardev 与 hwmon/iio 的共存特性直接失效）、`rmmod` 歧义；内核里 `i2c-` 前缀还容易被误读成总线适配器驱动 |
| `drivers/my_temp_driver.c` | 看不出总线、子系统、器件 |

### 1.2 新增一个驱动：只碰 4 处（互不覆盖）

1. **代码**：`drivers/<子系统>/<总线>-<器件>/{Kbuild,<子系统>_<总线>_<器件>.c}`
   （顶层 [`Makefile`](../Makefile) 是**递归发现** `drivers/**/Kbuild` 的，**不用改**）
2. **文档**：`doc/<子系统>/<总线>-<器件>/{设计文档.md,手动测试指南.md}`（通用规范留在 `doc/` 根）
3. **测试**：`tests/<子系统>/<总线>-<器件>/`（客户机内 `read_*.sh` + 宿主端到端 `verify_qemu.sh`）
4. **索引**：[`README.md`](../README.md) 的「驱动清单」「当前进度」各加一行

### 1.3 对外 ABI 的名字**不跟着**模块名变（重要纪律）

模块名/目录名是**工程内部**的整理手段；对外暴露的名字是**用户态 ABI**，一旦定了就别动：

| 名字 | 是否随模块名变 | 本驱动取值 |
|---|---|---|
| hwmon `name` | ❌ 不变 | `tmp105`（用户态按 `/sys/class/hwmon/*/name` 找设备） |
| sysfs 属性名 | ❌ 不变 | `temp1_input/max/min/max_alarm`（hwmon ABI） |
| 设备树 `compatible` | ❌ 不变 | `ti,tmp105`（设备树 ABI） |
| 字符设备节点 | ❌ 不变 | `/dev/tmp105`（chardev_i2c_tmp105） |
| ioctl 命令号 | ❌ 不变 | magic / 序号 / 方向 / 参数类型，`TMP105_IOC_*` |
| `.ko` 名 / `driver.name` / 日志前缀 | ✅ 跟着变 | `hwmon_i2c_tmp105.ko`、`/sys/bus/i2c/drivers/hwmon_i2c_tmp105` |

**ioctl 的 ABI 定义只写一份**：放在驱动目录的私有头（如
[`chardev_i2c_tmp105.h`](../drivers/chardev/i2c-tmp105/chardev_i2c_tmp105.h:1)），
驱动与用户态测试程序都 include 它；命令号一旦发布就不能改（老程序会拿到 `-ENOTTY`）。
用户态程序要 `-static` 交叉编译（目标 rootfs 常常没有动态库）。

所以改名只影响"我们自己的东西"（`.ko` 名、`rmmod` 名字、`unbind` 路径、日志），
**用户态代码零改动**。

### 1.4 `scripts/` 与 `tests/` 的分工（判定标准：换个驱动还能不能用）

| 位置 | 放什么 | 判定标准 | 本工程示例 |
|---|---|---|---|
| `scripts/` | **跨驱动通用**工具 | 换个驱动**不改一行**还能用 | `build.sh`（递归构建）、`run_qemu.sh`（起虚机 + 9p + QMP 开关）、`qmp_dev.py`（`--match/--prop` 通用 QMP） |
| `tests/<子系统>/<总线>-<器件>/` | **该驱动专属**的验证 | 里面出现具体器件名/属性名/地址 | `read_hwmon.sh`（找 `name=tmp105`）、`verify_qemu.sh`（端到端断言） |
| `doc/<子系统>/<总线>-<器件>/` | 该驱动的设计与手动测试 | 同上 | `设计文档.md`、`手动测试指南.md` |
| `doc/`、`README.md` | 全局规范与索引 | — | `开发规范.md`、驱动清单/进度 |

**规则**：一旦通用工具里出现"硬编码的器件名/属性名"，二选一 ——
① **通用化**（加参数，如 `qmp_dev.py --match/--prop`）；② 搬到 `tests/<子系统>/<总线>-<器件>/`。
反之，驱动专属脚本不要放 `scripts/`。

### 1.5 何时才抽公共代码

先单文件；真出现两点以上重复再抽，且优先"同目录私有头文件"（如 `hwmon_i2c_tmp105_regs.h`）。
跨驱动共享才放 `drivers/common/`，并注意：外部模块间共享符号需要显式导出（`EXPORT_SYMBOL*`），
或者把多个 `.c` 编进同一个模块（`hwmon_i2c_tmp105-y := a.o b.o`）——不要过早抽象。

## 2. 编码风格

- **checkpatch 必须干净**：`./scripts/build.sh checkpatch`（内部就是内核树的 `scripts/checkpatch.pl --no-tree --strict -f`）。
  - 权限用**八进制**（`0444` / `0644`），不要 `S_IRUGO`（checkpatch 会警告）。
  - 函数名/变量名**不要驼峰**（`tmp105_reg_to_mc`，不是 `..._to_mC`）。
  - 行宽 ≤ 80 列。checkpatch 是**按字节**数的（`length()` 作用在原始字节上），
    一个汉字 3 字节，所以中文行要更短。自检命令**必须锁字节口径**：
    `LC_ALL=C expand -t8 file.c | LC_ALL=C awk 'length($0) > 80'`。
    漏掉 `LC_ALL=C` 时 `awk` 在 UTF-8 locale 下按**字符**计数 → 中文行会**漏报**
    （踩过：4 行超宽被误判为通过，见 §8.8）。
- **参考树内同版本驱动**，不要照抄新版内核（4.9 与 5.x 的 API 有差异，例：`HWMON_CHANNEL_INFO()` 宏 4.9 没有）。
- 结构体/tab 对齐用 tab（宽度 8），续行对齐用空格。
- 头注释写清：器件规约、寄存器表、对外 ABI、换算公式、**本文件属于哪个总线/子系统**（让人一眼找到位置）。

## 3. 许可与合规

- 模块内 **`MODULE_LICENSE("GPL")`**：`hwmon`/`i2c` 的注册函数是 `EXPORT_SYMBOL_GPL`，非 GPL 模块拿不到符号。
- 每个新文件首行加 `// SPDX-License-Identifier: GPL-2.0`（脚本同理，用 `#`）。
- **对外 ABI 只用标准子系统**（hwmon sysfs 等）。**不加私有 ioctl** —— 一旦加了就是必须长期维护的稳定 ABI。

## 4. 资源与并发

- 优先 `devm_*`（`devm_kzalloc` / `devm_hwmon_device_register_with_info`）→ `remove` 通常不用做事，也不容易漏释放。
- 所有寄存器访问串行化（本模块用 `struct mutex lock`）；hwmon 的 `read/write` 回调是进程上下文，**可以睡眠**。
- 寄存器访问集中在**一个函数**里（本模块是 `tmp105_read_word()` / `tmp105_write_word()`），别让 I2C 调用散落各处。

## 5. 错误处理

- `i2c_smbus_*` 返回**负值即错误**，直接向上 `return`（常见 `-EREMOTEIO` = 从机 NACK、`-ENXIO`）。
- **不要在 probe 里做"必须成功"的读**：设备树写了节点但器件没挂上时 probe 仍应成功，让真正的读操作去报错。
- 数值换算用明确类型（`(s32)(s16)raw * 1000 / 256`）；单位按子系统要求（hwmon 温度用 **m°C**）。

## 6. 日志

| 场景 | 级别 | 例子 |
|---|---|---|
| probe 成功、关键配置 | `dev_info` | `hwmon_i2c_tmp105 0-0048: tmp105 at 0x48 on Synopsys DesignWare I2C adapter` |
| 可忽略的探测信息 | `dev_dbg` | `CONFIG=0x00 (shutdown=0, tm=0)` |
| 出错 | `dev_err`（但不要在每个读失败时刷屏） | — |

- 日志里带上**地址/总线名**；`dmesg | grep <模块名>` 一眼定位。

## 7. 提交与验收流程

```sh
# 1) 编译（递归构建 drivers/**）
make                       # 或 ./scripts/build.sh
# 2) 静态检查（必须 0 errors / 0 warnings）
./scripts/build.sh checkpatch
# 3) 端到端上机验收（按驱动单元跑；必须 FAIL=0）
tests/hwmon/i2c-tmp105/verify_qemu.sh
tests/chardev/i2c-tmp105/verify_qemu.sh
```

- 提交信息格式：`<模块名>: <动词> <内容>`，例如
  `hwmon_i2c_tmp105: 支持 temp1_max/min 的 0.5 °C 量化写入`。
- 提交前必须跑过 **步骤 1~3**，且验收脚本输出 `FAIL=0`。
- 改了器件侧行为（QEMU/dtbd）或模块名/路径时，同步更新该驱动的设计文档与 §12「实测结论」。

## 8. 已知坑（踩过的，别再踩）

1. **驱动绑定后 `i2c-dev` 会 EBUSY**：`insmod` 之后 `i2cget` 会报
   `can't set address to 0x48: Device or resource busy`（i2c-dev 的 `dev->driver ? -EBUSY : 0`）。
   要么把原始寄存器对照放在 `insmod` 之前，要么加 `-f`（`I2C_SLAVE_FORCE` 跳过占用检查，实测可用）；
   注意 `-f` 时驱动与 i2cget 会同时访问器件，只适合调试。另外：**同一从机地址同一时刻只能被一个
   器件驱动绑定**（`new_device` 会被 i2c 核心的 `i2c_check_addr_busy()` 拒绝），换驱动要 `rmmod` 或 `unbind`。
2. **QEMU 的 stdout 是块缓冲**：串口日志"何时可读"不确定，脚本里不要用 `sleep` + `grep` 赌时间；
   让客户机把结果写进 9p 共享目录再让宿主轮询（见 [`verify_qemu.sh`](../tests/hwmon/i2c-tmp105/verify_qemu.sh)）。
3. **`info qom-tree` 打印的是相对对象名**（如 `/device[10]`）而非完整 QOM 路径，不能直接喂给 `qom-set`；
   用通用的 [`qmp_dev.py`](../scripts/qmp_dev.py)
   （`--match <设备> --prop <属性>`；内部 `qom-list` 遍历 + 校验该属性存在）。
4. **QEMU tmp105 默认 9 位分辨率（0.5 °C 步进）**：`qom-set -6250` 读回 `-6500` 是**器件正常行为**，
   不是换算 bug；验收要用 `-6000` 这类可精确表示的值做等值断言。
5. **开机自带的 I2C WARN**：0.9 s 时 `i2c_dw_clk_rate` 的 `WARN_ON_ONCE`（DesignWare I2C 在 virt 上取不到输入时钟），
   与本驱动无关；日志扫描要从 insmod 之后开始。
6. **返回值二义性**（写传感器/测量类驱动必踩）：温度本身可以是负值（`-6250`），
   若把"测量值"当函数返回值，就无法区分"合法的负值"和"错误码 `-EINVAL`"。
   统一用 **`ret` + 出参**（`int *out`）：`ret < 0` 才是错误。
   （chardev_i2c_tmp105 的 `read()` 就踩过：负温度时 `cat` 报 `Invalid argument`。）
7. **测试脚本的两个坑**：① 9p 共享目录不保证允许直接执行 → 二进制先 `cp` 到 `/tmp`（tmpfs）再跑；
   ② `a; b > file 2>&1` 的重定向**只作用于 b** → 要写成 `( a; b ) > file 2>&1`。
8. **行宽自检的 locale 陷阱**：`expand -t8 f.c | awk 'length>80'` 看起来对，
   但 `awk` 的 `length` 按**字符**算（UTF-8 locale 下），中文注释行会**漏报**；
   checkpatch 的 `length()` 作用在未解码的字节上，按**字节**算。两者口径不同，
   于是出现\"自检 0 行超宽、checkpatch 报 4 行超宽\"。自检要跟 checkpatch 对齐：
   `LC_ALL=C expand -t8 f.c | LC_ALL=C awk 'length($0) > 80'`。
   推论：**别把 `LC_ALL=C` 只加在半条管道上**——它只作用于被加的那一个命令。
9. **Kbuild 的 `obj-m` 不能带连字符**：`obj-m := i2c-tmp105.o` 会被 Kbuild 当成
   参数分隔（`-` 开头的 `.o` 会被当选项）。所以**目录名用连字符**（`i2c-tmp105/`，
   给人/shell 看）、**文件名用下划线**（`hwmon_i2c_tmp105.c`，给 Kbuild 看），
   同一组信息两种合法拼写，见 §1.1。
