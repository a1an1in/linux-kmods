# 开发规范（linux-kmods）

> 适用范围：本工程里所有内核模块（当前是 [`tmp105_hwmon`](../drivers/tmp105_hwmon/tmp105_hwmon.c)）。
> 目标：**每个模块都能通过 `./scripts/build.sh checkpatch`（0 errors / 0 warnings）、
> 能用 `./scripts/verify_qemu.sh` 一键验收**。

---

## 1. 工程约定

| 项 | 约定 |
|---|---|
| 目录 | 一个模块一个目录：`drivers/<模块名>/`，里面至少 `Kbuild` + `<模块名>.c` |
| 构建 | 顶层 [`Makefile`](../Makefile) 自动发现 `drivers/*/Kbuild`，逐个用 `M=<dir>` 做外部模块构建；**不需要**在 `drivers/` 下再加 Makefile |
| 模块名 | 避免与内核自带驱动同名（例：本模块叫 `tmp105_hwmon.ko`，不叫 `tmp105.ko`，因为 [lm75.c](../README.md) 内部 handle 也叫 tmp105） |
| 内核树 | 默认 `/home/alan/workspace/linux-4.9.263`（arm64）；换树用 `KDIR=` 覆盖，且换树后先 `modules_prepare` |
| 产物 | 只把 `.ko` 交付到 rootfs；`*.o/*.mod.c/.tmp_versions` 等由 `.gitignore` 忽略 |

## 2. 编码风格

- **checkpatch 必须干净**：`./scripts/build.sh checkpatch`（内部就是内核树的 `scripts/checkpatch.pl --no-tree --strict -f`）。
  - 权限用**八进制**（`0444` / `0644`），不要 `S_IRUGO`（checkpatch 会警告）。
  - 函数名/变量名**不要驼峰**（`tmp105_reg_to_mc`，不是 `..._to_mC`）。
  - 行宽 ≤ 80 列。**中文注释按字节算**（一个汉字 3 字节），所以中文行要更短；
    检查命令：`expand -t8 file.c | awk 'length($0) > 80'`。
- **参考树内同版本驱动**，不要照抄新版内核（4.9 与 5.x 的 API 有差异，例：`HWMON_CHANNEL_INFO()` 宏 4.9 没有）。
- 结构体/tab 对齐用 tab（宽度 8），续行对齐用空格。
- 头注释写清：器件规约、寄存器表、对外 ABI、换算公式 → 让后来者不用翻数据手册。

## 3. 许可与合规

- 模块内 **`MODULE_LICENSE("GPL")`**：`hwmon`/`i2c` 的注册函数是 `EXPORT_SYMBOL_GPL`，非 GPL 模块拿不到符号（链接就会报 undefined）。
- 每个新文件首行加 `// SPDX-License-Identifier: GPL-2.0`（脚本同理，用 `#`）。
- **对外 ABI 只用已有的标准子系统**（hwmon sysfs）。**不加私有 ioctl**——一旦加了就变成必须长期维护的稳定 ABI。

## 4. 资源与并发

- 优先 `devm_*`（`devm_kzalloc` / `devm_hwmon_device_register_with_info`）→ `remove` 回调通常**什么都不用做**，也不容易漏释放。
- 所有寄存器访问串行化（本模块用 `struct mutex lock`）；hwmon 的 `read/write` 回调是进程上下文，**可以睡眠**。
- 寄存器访问集中在**一个函数**里（本模块是 `tmp105_read_word()` / `tmp105_write_word()`），别让 I2C 调用散落在各处。

## 5. 错误处理

- `i2c_smbus_*` 返回**负值即错误**，直接向上 `return`（常见 `-EREMOTEIO` = 从机 NACK、`-ENXIO`）。
- **不要在 probe 里做"必须成功"的读**：设备树写了节点但器件没挂上时，probe 仍应成功，让真正的读操作去报错（本模块只在 probe 里 `dev_dbg` 读一次 CONFIG）。
- 数值换算用明确类型：`(s32)(s16)raw * 1000 / 256`；单位按子系统要求（hwmon 温度用 **m°C**）。

## 6. 日志

| 场景 | 级别 | 例子 |
|---|---|---|
| probe 成功、关键配置 | `dev_info` | `tmp105 at 0x48 on Synopsys DesignWare I2C adapter` |
| 可忽略的探测信息 | `dev_dbg` | `CONFIG=0x00 (shutdown=0, tm=0)` |
| 出错 | `dev_err`（但不要在每个读失败时刷屏） | — |

- 日志里带上**地址/总线名**，多实例时不用猜；`dmesg | grep tmp105` 一眼定位。

## 7. 提交与验收流程

每一步都要有"可执行的证据"，不接受"应该没问题"：

```sh
# 1) 编译（外部模块，交叉编译）
./scripts/build.sh

# 2) 静态检查
./scripts/build.sh checkpatch          # 必须 0 errors / 0 warnings

# 3) 端到端上机验收（编译 + 起 QEMU + L1~L4 断言）
./scripts/verify_qemu.sh
```

- 提交信息格式：`<模块>: <动词> <内容>`，例如
  `tmp105_hwmon: 支持 temp1_max/min 的 0.5 °C 量化写入`。
- 提交前必须跑过 **步骤 1~3**，且 `verify_qemu.sh` 输出 `FAIL=0`。
- 改了器件侧行为（QEMU/dtbd）时，同步更新设计文档 §12「实测结论」。

## 8. 已知坑（踩过的，别再踩）

1. **驱动绑定后 `i2c-dev` 会 EBUSY**：`insmod` 之后 `i2cget` 会报
   `can't set address to 0x48: Device or resource busy`。原始寄存器对照要放在 `insmod` 之前。
2. **QEMU 的 stdout 是块缓冲**：串口日志"何时可读"不确定，脚本里不要用 `sleep` + `grep` 赌时间；
   让客户机把结果写进 9p 共享目录再让宿主轮询（见 [`verify_qemu.sh`](../scripts/verify_qemu.sh)）。
3. **`info qom-tree` 打印的是相对对象名**（如 `/device[10]`）而非完整 QOM 路径，不能直接喂给 `qom-set`；
   用 [`qmp_set_temp.py`](../scripts/qmp_set_temp.py)（`qom-list` 遍历 + 校验有 `temperature` 属性）。
4. **QEMU tmp105 默认 9 位分辨率（0.5 °C 步进）**：`qom-set -6250` 读回 `-6500` 是**器件正常行为**，
   不是换算 bug；验收时要用 `-6000` 这类可精确表示的值做等值断言。
5. **开机自带的 I2C WARN**：0.9 s 时 `i2c_dw_clk_rate` 的 `WARN_ON_ONCE`（DesignWare I2C 在 virt 上取不到输入时钟），
   与本驱动无关；日志扫描要从 insmod 之后开始。
